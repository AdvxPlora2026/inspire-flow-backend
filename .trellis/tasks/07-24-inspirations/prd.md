# 灵感数据关联项目

## Goal

为已登录的 B 站创作者提供独立的“灵感”资源，让一句尚未成熟的想法可以立即保存、追溯来源、关联一个或多个项目，并由 InspireFlow Agent 继续推进为可执行的创作内容。

## Background

- 系统已有按用户隔离的项目、对话和消息资源，均使用 UUID 标识。
- 当前 Agent 提示词要求捕捉和推进灵感，但后端没有灵感数据模型、REST API 或持久化工具。
- 项目已有 Agent CRUD 工具，并对创建和删除执行确认流程。

## Requirements

### R1. 灵感数据

- 灵感属于一个用户，必须通过鉴权访问，并与其他用户的数据完全隔离。
- 灵感包含：
  - UUID。
  - 可选标题；Agent 在有把握时可以生成标题。
  - 必填正文。
  - 状态：`inbox`、`developing`、`converted` 或 `archived`，默认 `inbox`。
  - 来源类型：`manual`、`agent` 或 `voice`，公共创建接口默认 `manual`。
  - 可选来源对话 UUID 和来源消息 UUID。
  - 创建时间和更新时间。
- 标题和正文使用明文 SQLite 字段，以支持中文关键词查询和数据库分页。
- 新建且尚未归类的 `inbox` 灵感允许暂时没有项目或来源引用。

### R2. 项目关联

- 灵感与项目为多对多关系；一条灵感可以关联零个、一个或多个同属当前用户的项目。
- 创建或 `PATCH` 灵感时，可以传入 `project_ids` 一次性设置完整关联集合。
- 提供独立的增量关联接口，支持逐个添加或移除项目。
- 项目详情返回 `inspiration_count`，不内嵌完整灵感列表。
- `/api/v1/projects/{project_id}/inspirations` 返回该项目的分页灵感列表。
- 灵感详情返回关联项目的 UUID、标题和图标摘要。

### R3. 来源追溯与删除

- Agent 创建灵感时，尽可能记录当前对话和当前用户消息；手动或语音创建允许来源引用为空。
- 删除项目或来源对话时，不能静默留下因本次删除而失去全部关联的灵感。
- 删除前计算影响范围：
  - 如果灵感仍有关联项目或有效来源，保留灵感，只清理被删除的关联。
  - 如果灵感会失去最后一个项目和来源引用，首次删除请求返回冲突和受影响灵感列表，不执行删除。
  - 用户确认后，重试删除并同时删除这些将变为孤立数据的灵感。
- 直接删除灵感时，同时删除其项目关联记录。
- 明确移除最后一个项目关联属于用户主动整理行为；当灵感仍为 `inbox` 时允许回到未归类状态。

### R4. 查询能力

- 灵感列表按当前用户隔离并分页。
- 支持按项目 UUID、状态和来源类型筛选。
- 支持在标题和正文中进行关键词搜索。
- 支持按创建时间或更新时间升序或降序排列。
- 默认按更新时间倒序排列，并使用 UUID 作为稳定的次级排序键。

### R5. REST API

- 在现有 `/api/v1` 下新增灵感资源，不迁移已有 API。
- 提供创建、列表、详情、修改和删除灵感的 RESTful 接口。
- 提供项目关联的添加、移除以及按项目读取灵感的接口。
- 未知 UUID 和其他用户的 UUID 返回同一种 `404`，不得暴露资源是否属于其他用户。
- 空正文、非法状态、非法来源、越权项目关联和空补丁必须返回稳定的错误响应。

### R6. Agent 行为与工具

- Agent 工具支持创建、查看、列出、编辑和删除灵感，以及添加、移除灵感与项目的关联。
- 项目创建工具支持在用户确认创建项目后，将指定的已有灵感同时关联到新项目。
- 用户表达出清晰、可识别的创作想法时，Agent 自动创建灵感并告知保存结果。
- 内容含糊或更像一般讨论时，Agent 先询问是否保存，不直接落库。
- Agent 不得自行决定删除灵感或项目：
  - 用户提出删除后，先展示影响范围。
  - 用户在后续一轮明确确认后才能执行。
  - 级联删除孤立灵感时，确认信息必须列出受影响灵感。
- 编辑和增减项目关联不要求二次确认，但 Agent 必须告知操作结果。
- 工具只能从运行上下文取得当前用户、对话和消息标识，不接受模型传入 `user_id`。

### R7. 文档与隐私说明

- 提供灵感 REST API、Agent 工具和删除确认流程的交接说明。
- 明确说明标题和正文为明文存储：接口有鉴权和用户隔离，但拥有 SQLite 文件读取权限的人可以看到灵感内容。

## Acceptance Criteria

- [x] 登录用户可以创建标题可空、正文必填的灵感；默认状态为 `inbox`、默认来源为 `manual`。
- [x] 登录用户可以读取、编辑、删除和分页查询自己的灵感，无法探测或访问其他用户的灵感。
- [x] 一条灵感可以关联多个自有项目，并可通过全量替换或增量接口安全调整关联。
- [x] 关联其他用户或不存在的项目失败，且不会产生部分写入。
- [x] 状态、来源、项目、关键词、排序和分页组合查询返回稳定且正确的结果。
- [x] 项目详情返回准确的 `inspiration_count`，项目灵感接口返回分页数据，灵感详情返回项目摘要。
- [x] 删除项目或对话不会静默产生孤立灵感；需要级联时先返回影响列表，确认后在一个事务中完成删除。
- [x] Agent 能自动保存明确灵感、管理灵感与项目关联，并在项目或灵感删除前执行确认流程。
- [x] Agent 创建的灵感在耐久对话中记录当前对话和用户消息来源，直接 Agent 调用允许来源为空。
- [x] Alembic 可从现有 head 升级并安全降级该功能；迁移、服务、API 和 Agent 工具均有自动化测试。
- [x] Ruff、格式检查和 `pytest -W error` 全部通过，稳定测试不调用真实模型或公网。
- [x] 交接文档包含请求示例、响应字段、错误与级联确认示例，以及明文存储说明。

## Out of Scope

- 前端界面与交互实现。
- 图片、附件、标签、收藏、版本历史和软删除。
- 向量检索、语义搜索、相似灵感推荐和自动合并。
- 自动将既有 STT 任务结果写入灵感；首版只预留并支持 `voice` 来源。
- 多用户共享灵感、协作者权限和跨用户项目关联。
- 对灵感标题或正文做应用层加密。
- 未经用户确认自动创建或删除项目。

## Technical Notes

- 当前代码采用同步 SQLAlchemy 2.0、SQLite、服务层事务和可逆 Alembic 迁移。
- 路由只负责 HTTP 与依赖注入；验证在 Pydantic，事务与业务规则在服务层，查询在仓储层。
- Agent FunctionTool 必须继续保持 `services/agent/func/` 下“一工具一模块”的结构，并通过注册表统一排序。
