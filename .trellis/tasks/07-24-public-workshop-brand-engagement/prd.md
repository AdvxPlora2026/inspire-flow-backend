# 创作者公开橱窗与品牌互动

## Goal

为 InspireFlow 增加创作者公开橱窗和品牌合作入口。创作者可以先预览再发布自己的
公开资料，精确控制字段对普通访客、品牌组织成员和指定品牌的可见性；品牌可以发现
创作者、关注或表达合作意向；创作者在站内收件箱处理这些互动。Agent 对话同时
支持流式返回，所有业务写接口具备可重试的幂等语义。

## Background

- 当前后端只有一种 Bearer 用户身份，没有独立品牌主体或品牌认证状态。
- 用户已有公开基础资料、结构化创作者资料、内部 `profile_text`、项目、灵感和
  持久 Agent 对话。
- API 统一使用 `/api/v1`，错误使用稳定的 `error.code` 信封。
- 当前 Agent 消息接口一次性返回完整 JSON，写接口没有统一幂等键。
- 联系方式和社交账号尚未建模，不能继续塞进自由文本画像。

## Requirements

- R1：创作者可以预览、发布、更新和撤回 Public Workshop。撤回后公共入口立即
  不可见，草稿和历史业务数据继续保留。
- R2：可发布字段使用四级可见性：
  `private`、`workshop_public`、`brands_only`、`authorized_brands`。
- R3：品牌发现列表只能返回调用方有权看到的字段，不能先返回完整对象再由前端
  隐藏。
- R4：品牌可以一键关注创作者，也可以提交合作意向；重复请求必须幂等。
- R5：创作者有品牌互动收件箱，可以查看关注和意向，并维护已读状态。
- R6：联系方式授权由服务端判断和解析。未授权响应不能包含联系方式原文、可逆
  密文、部分掩码之外的推断材料或对象存储地址。
- R7：社交账号与联系方式分别建模，各自有字段级可见性规则；不使用
  `profile_text` 代替结构化数据。
- R8：Agent 消息支持流式传输，并保留现有持久对话、消息顺序、上下文压缩、
  工具调用和记忆提取能力。
- R9：所有业务写操作接受幂等键。相同用户、接口和幂等键重试时返回第一次完成
  的结果；相同键配不同请求体必须拒绝。
- R10：所有新资源按用户或品牌主体隔离，跨主体访问使用 404，权限不足使用稳定
  的 403 错误码。
- R11：数据库迁移可从当前最新版本升级，并有 downgrade 路径。
- R12：新增 API、枚举、权限矩阵、流式协议和幂等语义写入交接文档。
- R13：复用现有 `User` 登录与 `AuthSession`。新增品牌组织及成员关系；同一用户
  可以同时拥有创作者资料并加入品牌组织。品牌关注、意向和授权以品牌组织为主体，
  不直接归属某个成员账号。
- R14：`brands_only` 对所有已登录且属于相应品牌组织的成员开放，不要求品牌
  通过平台认证。原始联系方式不能使用 `brands_only`，只能设为 `private` 或
  `authorized_brands`，避免自建品牌直接取得敏感信息。
- R15：`authorized_brands` 是创作者对品牌组织授予的独立权限。关注、提交意向、
  已读或处理意向都不自动授权。授权对该品牌组织的所有成员生效，创作者可撤销；
  服务端在每次读取时按当前授权解析字段。
- R16：首版不做“品牌 × 单个字段”的授权矩阵。品牌获得授权后可读取该创作者
  所有标记为 `authorized_brands` 的字段；字段仍可随时改回 `private`。
- R17：Public Workshop 使用草稿和已发布快照。创作者编辑草稿，预览按草稿生成；
  首次发布或再次发布时原子替换线上快照。草稿修改不会立即影响线上内容。
- R18：撤回只让线上快照不可访问，不删除草稿、结构化资料、社交账号、联系方式、
  品牌授权或历史互动。再次发布可以继续使用现有草稿。
- R19：首版橱窗资料包含昵称、头像、橱窗标题、简介、创作者身份、内容方向和合作
  偏好。昵称与头像可从公开用户资料带入草稿，但发布后以快照为准。
- R20：创作者可以从自己的现有项目中选择精选作品。发布时复制项目标题、类型、
  受众、简介和图标到线上快照；内部项目后续变化不自动更新已发布作品。
- R21：每个创作者资料字段、每条社交账号和每条联系方式有独立可见性；精选作品
  以整张快照卡片为单位设置可见性。
- R22：合作意向是轻量状态对象，品牌可附带可选留言，不强制提交预算或档期。
  状态为 `pending`、`accepted`、`declined`、`withdrawn`。
- R23：同一品牌组织和创作者同一时间最多一条 `pending` 意向。创作者可接受或
  拒绝；品牌成员可在处理前撤回。重复发送返回现有待处理记录，进入终态后可新建。
- R24：接受意向不授予联系方式权限。首版不做意向内的多轮聊天。
- R25：保留现有
  `POST /api/v1/conversations/{conversation_id}/messages` JSON 接口，新增独立的
  `POST /api/v1/conversations/{conversation_id}/messages/stream` SSE 接口。
- R26：SSE 至少包含 `turn.started`、`response.delta`、`tool.started`、
  `tool.completed`、`turn.completed` 和 `turn.failed`。工具事件只返回安全名称和
  执行状态，不返回原始参数、内部结果或敏感信息。
- R27：流开始前的鉴权、校验和资源错误继续使用普通 HTTP 错误信封；响应头发出后
  的执行失败通过 `turn.failed` 稳定错误事件结束。
- R28：所有已鉴权业务写接口强制要求 `Idempotency-Key`。覆盖用户与创作者资料、
  记忆、项目、灵感、对话、Agent 消息、STT、Public Workshop、社交账号、
  联系方式、品牌互动和授权写操作。
- R29：注册和登录不属于已鉴权写请求；注销携带 Bearer Token，因此也必须要求
  幂等键。缺少必需 Header 时返回
  `400 idempotency_key_required`；同作用域同键不同载荷返回
  `409 idempotency_key_reused`，相同请求仍在执行时返回
  `409 idempotency_request_in_progress`，错误体包含 `retryable: true`。
- R30：幂等唯一作用域固定为当前登录用户、HTTP 方法、规范化实际路径和 key
  digest，不再把品牌组织作为额外作用域。查询参数和请求体属于请求指纹；相同
  作用域、键和请求指纹重试时重放第一次完成的状态码与响应。
- R31：普通幂等记录至少保留完成后 24 小时。缓存的响应使用上下文密钥加密；服务
  通过定期清理和写入时的限量清理删除过期记录。授权和结算响应至少保留到商业
  任务截止时间后 24 小时。过期后相同键按新请求处理。
- R32：SSE 客户端断线后，已开始的 Agent 本轮继续在服务端执行并持久化最终消息、
  记忆和工具副作用。运行中同键请求返回
  `409 idempotency_request_in_progress`；完成后同键重放 `turn.started` 和
  `turn.completed`，不保存或重放全部文本增量。
- R33：服务进程重启或运行超时后，遗留运行记录进入可恢复失败状态并释放对话锁。
  客户端使用新的幂等键重新发起一轮；内部 Agent 写工具必须使用稳定的派生幂等
  作用域，避免已完成工具调用被重复执行。
- R34：品牌组织首版只有 `owner` 和 `member`。创建者自动成为 owner；owner
  可以修改品牌资料和管理成员，普通 member 可以发现、关注创作者并发送或撤回
  意向。
- R35：成员通过邀请加入。owner 按现有用户昵称创建邀请，受邀用户接受后成员
  关系才生效；允许拒绝或撤销邀请。最后一名 owner 不能退出或被移除，必须先
  转移所有权。
- R36：所有品牌作用域 API 在路径中显式携带 `brand_id`，不使用隐式当前品牌或
  `X-Brand-Id`。服务端每次校验当前用户的有效成员关系；品牌 ID 通过规范化实际
  路径自然隔离，不再作为独立幂等作用域列。
- R37：社交账号是独立结构化记录，字段至少含 `platform`、`handle`、
  `profile_url`、`visibility`、`sort_order`。平台支持 `bilibili`、`douyin`、
  `xiaohongshu`、`weibo`、`zhihu`、`youtube`、`other`，允许全部四种可见性。
- R38：联系方式是独立结构化记录，字段至少含 `type`、`label`、`value`、
  `visibility`、`sort_order`。类型支持 `email`、`phone`、`wechat`、`qq`、
  `telegram`、`other`；可见性只允许 `private` 或 `authorized_brands`。
- R39：联系方式原值使用上下文密钥加密。服务端按类型校验和规范化；品牌通过
  当前授权检查后，响应才包含 `value` 和可用的 `action_uri`。未授权响应不包含
  原文或可逆材料。
- R40：品牌关注是品牌组织与创作者之间唯一的软状态关系，使用 `active/inactive`。
  `PUT` 关注、`DELETE` 取消；重复调用保持幂等。
- R41：首次关注或取消后再次关注，会更新时间并把创作者收件箱中的关注项重新
  标记为未读。取消关注保留历史并显示当前已取消状态；发现页和关注列表只统计
  `active`。
- R42：仅橱窗所有者可预览草稿。预览支持 `owner`、`public`、`brand`、
  `authorized_brand` 四种模拟视角；模拟不改变真实授权。线上读取始终按调用方
  真实身份、品牌成员关系和授权记录投影字段。
- R43：品牌发现列表支持 `query`、`content_focus`、`creator_identity`、
  `project_type`、`followed`、`sort_by`、`sort_order`、`limit` 和 `offset`。
  `sort_by` 只支持 `published_at`、`updated_at`，默认 `updated_at desc`。
- R44：发现搜索和筛选只使用当前品牌有权看到的已发布字段。隐藏字段不能用于
  匹配、排序、计数或返回，避免通过命中结果推断私有内容。

## Acceptance Criteria

- [ ] 创作者能预览未发布草稿，发布后公共或品牌发现入口可见，撤回后不可见。
- [ ] 四级字段可见性在匿名访客、普通登录用户、普通品牌成员、已授权品牌和资源
  所有者五类调用方下有自动化测试。
- [ ] 用户能创建品牌组织；owner/member 权限、邀请接受/拒绝/撤销和最后一名
  owner 保护均有自动化测试。
- [ ] 品牌发现列表支持稳定分页，响应中不存在越权字段。
- [ ] 品牌关注和合作意向能进入创作者收件箱；创作者可以标记单条或批量已读。
- [ ] 取消后再次关注会恢复同一关系并重新标为未读；合作意向状态只允许规定的
  主体执行合法转换。
- [ ] 联系方式只有在服务端确认授权后才会返回可用值。
- [ ] 社交账号和联系方式可以独立创建、修改、删除和调整可见性。
- [ ] 橱窗发布使用不可变快照；草稿修改不影响线上，精选项目发布后不跟随内部
  项目变化，撤回不删除草稿。
- [ ] Agent 流式接口能持续发送事件，完成后消息仍完整落库；断流和模型失败有
  明确的终止事件或错误行为。
- [ ] 所有 Bearer 鉴权写接口缺少幂等键时返回 400，并覆盖首次请求、规范化 JSON
  重放、同键不同载荷复用、实际路径隔离、并发重试、multipart 文件摘要和保留期。
- [ ] 原有非流式 API 保持兼容，现有测试继续通过。
- [ ] Alembic 升降级、Ruff、格式检查和完整测试套件通过。

## Out of Scope

- 品牌付款、合同签署、发票和站外消息发送。
- 对品牌资质做人工审核后台。
- 搜索推荐算法、广告竞价和商业排序。
- 从第三方平台自动抓取社交账号数据。

## Technical Notes

- 现有 `User`、`AuthSession` 和 Bearer 依赖只表达“登录用户”，没有角色、
  品牌组织、成员关系或品牌认证字段。
- 已确认不增加互斥的 creator/brand 账号类型。认证后从品牌成员关系解析当前
  可操作的品牌组织；品牌作用域接口通过路径参数明确组织，不猜测当前品牌。
- 现有 OpenAI Agents SDK 提供 `Runner.run_streamed()`，可以在不更换模型适配层的
  前提下增加流式执行；仍需设计 SSE 事件与数据库事务边界。
- 现有项目关联和 STT worker 只有局部幂等行为，没有通用
  `Idempotency-Key` 存储或请求指纹机制。
- 当前公开用户响应只含昵称和头像，创作者结构化资料全部要求登录；Public
  Workshop 需要单独的发布快照或发布状态，不能直接把内部资料对象公开。
